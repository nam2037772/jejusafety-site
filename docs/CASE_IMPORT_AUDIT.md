## 4. 이미지 반입 계획

원본 이미지는 vault 안 파일이 아니라 **네이버 블로그 CDN 주소**(`postfiles.pstatic.net`)입니다.

```
tools/import-cases.js   (신규)
  ① vault의 안전시설-0NN.md 를 읽기 전용으로 파싱
  ② 이미지 URL을 순서대로 수집 → 섹션 마커(작업전/작업중/작업후, 시공전/시공후)로 역할 배정
  ③ C:\Projects\jejusafety-site\assets\images\cases\0NN\ 에 리네임 저장
        before-01.jpg / process-01.jpg / after-01.jpg / product-01.png
  ④ assets/js/cases.js 뼈대 생성 (본문은 사람이 다듬음)

  ▶ vault 경로에는 절대 쓰지 않습니다 (기존 ainsafe-site 와 동일한 쓰기 금지 가드 이식)
  ▶ 이미 받은 파일은 건너뜁니다
  ▶ 원본 파일명은 버립니다 → 003의 학교 실명 노출이 여기서 자동 차단됩니다
```

이미지 폴더는 번호만 씁니다(`cases/001/`). slug 이 바뀌어도 폴더를 옮길 필요가 없습니다.

**역할 자동 배정 신뢰도**

| 신뢰 | Case | 방식 |

| 높음 | 001 | `[작업전/중/후 사진]` 마커로 정확히 분리 |
| 높음 | 002·003·004 | `시공전 / 시공후` 표에서 열 위치로 분리 |

### 007 보류 사유 (공개 검토 필요)

  → 해당 컷을 게시 목록에서 제외하고, 배경에 상호가 없는 1장만 남겼습니다.
- 원문 본문에 있던 **개인 휴대폰번호(010-…)** 는 사이트로 옮기지 않았습니다.
  대표번호 `1660-4019` 만 사용합니다. `check-site.js` 가 휴대폰번호 패턴을 검출해 재발을 막습니다.

  **발주처 확인 후 `published: true` + `review.disclosure: 'ok'` 로 바꾸고 다시 빌드하면 즉시 게시됩니다.**

### 003 실명 노출 처리

## 7. 남은 확인 사항

| # | 항목 | 현재 처리 | 확인되면 |
| --- | --- | --- | --- |
| 1 | **007 게시 여부** | `published: false` | `true` 로 바꾸고 재빌드 |
| 2 | **시공일** (9건) | `date: null` | `cases.js` 의 `_dateHint` 주석 참고해 `YYYY-MM` 기입 |
| 3 | **지역** (002·004·005·006·007·008·009) | `region: null` | `'제주시'` 또는 `'서귀포시'` 기입 → 지역 필터·제목에 반영 |
| 4 | **발주처 유형** (005~009) | `customerType: null` | enum 값 기입 → 발주처 필터에 반영 |
| 5 | **001 발주처 실명** | `서귀포시청` 표기 중 | 비공개 원하시면 `customerName: null`, `customerLabel: '서귀포시 관공서'` |

위 값들은 전부 **비워 둔 상태로도 사이트가 정상 동작**합니다.
채우면 필터·제목·구조화데이터가 자동으로 풍부해집니다.
