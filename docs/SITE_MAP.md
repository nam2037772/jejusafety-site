## 2. 서비스 분류 (Service Taxonomy)

제시된 5개 분류를 유지합니다. 실제 수행 작업 15종이 모두 1:1로 귀속되며 빈 칸·중복이 없어 재정의하지 않았습니다.

### 분류 원칙

- **분류 기준 = 시설의 위치와 보호 대상** (공법이나 자재가 아님)
  → 담당자는 "내 관할 어디에 있는 시설이 문제인가"로 생각하기 때문
- 한 시설이 두 분야에 걸치면 **주 분야 1개**에 두고 다른 쪽은 "관련 시설"로 링크만 겁니다 (URL 중복 방지)
- 유지보수(4번)는 시설 종류가 아니라 **작업 성격** 축입니다. 노후·부식·파손 대응의 진입 지점 역할

수단: ☎ 1660-4019 · SMS · 이메일(제목·본문 자동 작성 `mailto:`) · (개설 시 카카오채널)

`?type=` 쿼리로 문의 유형을 미리 선택합니다 — `site`(현장확인) `quote`(견적) `install`(설치) `supply`(자재납품).

> 자체 서버가 없으므로 **폼 POST 백엔드를 만들지 않습니다.** `mailto:` / `tel:` / `sms:` 로 처리합니다.
> **다만 향후 사진 첨부형 견적문의 폼을 붙일 수 있도록 구조를 열어 둡니다.**
> 입력값을 모으는 부분(`buildInquiry()`)과 보내는 부분(`sendInquiry()`)을 분리해 두고,
> `CONTACT_CHANNELS.externalForm` 에 주소가 들어오면 CTA가 그 폼으로 전환됩니다.
> 즉 폼 도입 시 고쳐야 할 곳은 **config 한 줄 + `sendInquiry()` 한 함수**입니다.

페이지를 손으로 쓰면 15장까지는 괜찮지만 사례가 100건이 되면
브랜드 표기·JSON-LD·canonical 규칙이 반드시 어긋납니다.
`tools/lib/layout.js` 한 곳에서 만들면 **어긋날 수가 없습니다.**
`check-site.js` 가 그 결과를 다시 검사합니다.


### 기술 선택

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 프레임워크 | 없음 (HTML + CSS + Vanilla JS) | MVP 원칙 |
| 빌드 | Node 스크립트, 의존성 0 | `npm install` 불필요. 어디서든 `node` 만 있으면 동작 |
| 배포 | GitHub Pages (`.nojekyll`) | 서버·DB 없음 |
| CMS | 없음 — 데이터 파일 직접 편집 + AI 구조화 | "복잡한 CMS 금지" |
| 폼 | `mailto:` / `tel:` / `sms:` | 백엔드 없음. 외부 폼 전환 지점만 열어 둠 |
| 폰트 | 시스템 폰트 스택 | 모바일 속도 |
| 이미지 | 원본(w966) + 썸네일(w773) 2단, `loading="lazy"` + `width/height` | CLS 0, 목록 전송량 절감 |
